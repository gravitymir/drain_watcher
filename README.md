# drain_watcher

Логгер тока утечки автомобильного аккумулятора: шунт в минусе аккумулятора,
плата-датчик на INA228 снимает с него напряжение и отдаёт замеры по I2C внешнему
контроллеру (ESP32 и т.п.). Контроллер питается от пауэрбанка, поднимает точку доступа
Wi-Fi и отдаёт веб-страницу с историей.

- [`hardware/`](hardware/) — плата KiCad 10 (схема, разводка, гербера, BOM/CPL для JLCPCB)
  и скрипты, которые её собирают. Подробности — в [hardware/README.md](hardware/README.md).
- [`firmware/ina228/`](firmware/ina228) — драйвер датчика на Rust, `no_std`, поверх
  `embedded-hal 1.0`. Без привязки к контроллеру: ему нужна только шина I2C, так что
  он одинаково встанет и в ESP-IDF, и в голый `esp-hal`.
- Прошивка контроллера (ESP32, Wi-Fi AP и веб-страница с историей) — будет здесь же.

## Драйвер INA228

Главное, ради чего он написан, — два диапазона по шунту и корректный переход между ними.
Ток утечки живёт в десятках миллиампер, и узкая шкала даёт по нему вчетверо лучшее
разрешение; подробности и цифры — в [hardware/README.md](hardware/README.md#измерение-два-диапазона-и-калибровка).

```rust
use ina228::{Ina228, Range, DEFAULT_ADDRESS};

// Шунт 2.5 мОм, верх шкалы 35 А. Стартуем на узкой шкале — машина спит.
let mut sensor = Ina228::new(i2c, DEFAULT_ADDRESS, 0.0025, 35.0);
sensor.init(Range::Narrow)?;

loop {
    // Сам уйдёт на широкую шкалу, если блок проснулся, и вернётся обратно.
    let m = sensor.measure_autoranged()?;
    log(m.current_a, m.bus_v, m.die_c);
}
```

`set_range` переписывает `SHUNT_CAL` вместе с `ADCRANGE` — поменять одно без другого
через этот API нельзя, а именно так и получается тихая ошибка в четыре раза.

Сборка и тесты:

```bash
cd firmware/ina228 && cargo test
```
